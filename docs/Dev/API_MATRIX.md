# Pillar API Matrix

This catalog is the `/v1` endpoint control surface for Pillar Mission Control. It aligns the developer-friendly public API grammar in [Architecture 03](../Architecture/03_Pillar%20API%20Grammar%20v1.md), public objects in [Architecture 04](../Architecture/04_Object%20Model.md), webhook semantics in [Architecture 10](../Architecture/10_Event_Webhook%20System.md), security scopes in [Architecture 12](../Architecture/12_Security.md), and phase ownership in the Dev plan.

Invariant: deployment mode (`hosted`, `customer-validator`, `self-hosted`) changes infrastructure wiring only; it must not change any `/v1` request grammar, response grammar, scope, idempotency, event, ledger operation, pagination, or expansion behavior.

## 1. Method conventions

| Method shape                     | Meaning                                                                   | Idempotency rule                           | Pagination rule                                             | Event rule                                                             | Ledger rule                                                            | Owning ticket |
| -------------------------------- | ------------------------------------------------------------------------- | ------------------------------------------ | ----------------------------------------------------------- | ---------------------------------------------------------------------- | ---------------------------------------------------------------------- | ------------- |
| `GET /v1/<plural>/:id`           | Retrieve one object visible to the caller.                                | Not idempotency-keyed; HTTP-safe.          | No.                                                         | Never emits `evt_*`.                                                   | Never creates `command_requests`.                                      | P2.C01        |
| `GET /v1/<plural>`               | List objects with cursor pagination.                                      | Not idempotency-keyed; HTTP-safe.          | Yes, unless the resource has no list endpoint.              | Never emits `evt_*`.                                                   | Never creates `command_requests`.                                      | P2.C01        |
| `POST /v1/<plural>`              | Create a config object, intent, job, or ledger-backed resource.           | Requires `Idempotency-Key`.                | No.                                                         | Emits only after config mutation or projected ledger/job state exists. | Creates `command_requests` only for ledger-backed workflows.           | P2.C04        |
| `POST /v1/<plural>/:id`          | Update a config object when PATCH is not used.                            | Requires `Idempotency-Key`.                | No.                                                         | Emits config/update event where subscribed.                            | Never creates `command_requests` unless explicitly an economic action. | P2.C04        |
| `POST /v1/<plural>/:id/<action>` | Action endpoint such as confirm, cancel, release, rotate, replay, revoke. | Requires `Idempotency-Key`.                | No, except replay range action accepts filters in the body. | Emits action-specific events after durable state change.               | Creates `command_requests` only for ledger-backed actions.             | P2.C04        |
| `DELETE /v1/<plural>/:id`        | Soft-delete or archive config-only object.                                | Requires `Idempotency-Key`.                | No.                                                         | Emits config deletion/disabled event where subscribed.                 | Never creates `command_requests`.                                      | P6.H01        |
| `PATCH /v1/<plural>/:id`         | Reserved but not used in v1.                                              | If introduced, requires `Idempotency-Key`. | No.                                                         | Same as update.                                                        | Same as update.                                                        | P2.C04        |

## 2. Header matrix

| Header                        | Required when                                                                                        | Applies to                                                                | Validation                                                                                                                                              | Failure status                                                                                   | Owning ticket |
| ----------------------------- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ | ------------- |
| `Authorization: Bearer <key>` | Every `/v1` request except explicitly public documentation assets outside this matrix.               | All resources.                                                            | API key prefix, hash, status, mode, tenant, scope, constraints, rate bucket.                                                                            | `401 authentication_error` when missing/invalid; `403 permission_error` when insufficient scope. | P8.K01        |
| `Idempotency-Key`             | Every mutating `POST`, action `POST`, `DELETE`, and future `PATCH`.                                  | Create/update/action/delete endpoints.                                    | 1-255 chars, high entropy recommended, scoped by tenant + livemode + method + path + key, request fingerprint includes normalized body and API version. | `400 invalid_request_error` if missing; `409 idempotency_error` on mismatched reuse.             | P3.D03        |
| `Pillar-Version`              | Recommended on every request; required for SDK golden coverage and webhook endpoint version pinning. | All resources.                                                            | `YYYY-MM-DD.codename` or account default. Must not expose Canton internals.                                                                             | `400 version_error` for unsupported version.                                                     | P2.C05        |
| `Pillar-Request-Id`           | Response header on every request.                                                                    | All resources.                                                            | Generated by API edge; stable for the request attempt.                                                                                                  | N/A.                                                                                             | P3.D02        |
| `Pillar-Mode`                 | Response/debug header derived from key environment.                                                  | All resources.                                                            | `test` or `live`; not the same as deployment mode.                                                                                                      | N/A.                                                                                             | P2.C03        |
| `Pillar-Signature`            | Webhook callback deliveries sent by Pillar to customer endpoints.                                    | Webhook consumers, not inbound `/v1` calls except signature-test tooling. | HMAC-SHA256 over `timestamp.raw_body`, endpoint secret, timestamp tolerance, constant-time compare.                                                     | Consumer rejects; Pillar records delivery failure and retries.                                   | P6.H02        |
